Customers already store a unique referral code and an optional referred-by link, but nothing lets a signed-in customer claim someone else's code after signup or see how many people they have successfully referred.
Provide a redemption path on the customer API. An authenticated user posts /customers/profile/referral and passes in a POST body in JSON format containing a string of "code". In case the code is also another customer, but not the caller's own, and the caller has never been referred before, persist the relationship and give the referrer the fixed “Loyalty Point” bonus value of “100” (to the totalLoyaltyPoints of the referrer). Return HTTP 200 and JSON body with referredById (referrer's customer id) and a value for pointsAwarded of 100. If the code doesn't exist, return 404 with an error field containing “referral_not_found.” If the code is the caller's own code, or the caller already has a referredById, return 409 and error code referral_not_eligible. Codes are compared case-sensitively after removing whitespace from the front and end of the code; if the code is empty or only whitespace, it is returned as 400 and error invalid_referral_code.
Also expose a read-only summary on the existing authenticated GET /customers/profile response: referralCount (how many customers list them as referredById) and totalLoyaltyPoints (current balance after any redemptions).
If the caller attempts to redeem a second time, the answer should be referral_not_eligible and the points should not be redeemed again. If the same customer makes a claim concurrently, the referrer should not be given two claims. If a caller never interacts with any referrals end-points, existing auth, listing, wallet and order flows remain unaffected.
